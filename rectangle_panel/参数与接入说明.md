# 固定基准照片的矩形标定版

打开 http://127.0.0.1:7861 ，或双击上一级的“启动矩形标定版.bat”。原版点标注页面仍在 7860，原版 app.py 和 matcher_demo.py 没有修改。

## 第一次标定

基准照片已从你的上传记录复制为 reference.png（1080×1920），固定 key_1 至 key_9、key_0、key_ok 共 11 个名称。原来的中心点以黄色十字显示，仅帮助找到按键。中心点没有宽高信息，未据此伪造矩形。

1. 选择一个按钮，在基准照片上按住鼠标，从区域一角拖到对角。矩形应覆盖你原先用于深度统计的按键区域。
2. 对全部 11 个按钮重复操作。可以放大照片、重画当前框，或输入 x1/y1/x2/y2 微调。
3. 点击“保存并固定 11 个矩形”。程序把标定写入 template.json，之后打开页面自动恢复；每次保存都会在 template_history 中备份上一版。
4. 上传同一面板的新视角照片，点击“开始映射”。下载结果包含 mapping.json、原始实时图片、预览和 11 张单按钮掩膜。

标定中尚未保存的框会在当前浏览器保存为草稿。换浏览器不会读取这些草稿，因此应点击保存写入本机。导出标定 JSON 可另外保留备份。

## 参数说明

| 参数 | 默认值 | 含义与调整影响 |
|---|---|---|
| 模型权重 | outdoor | 按你确认的截图参数固定；indoor 可用于比较。切换权重会释放当前模型与参考缓存，再重新加载，不能把 indoor 理解为一定最适合所有室内面板。 |
| 匹配置信度 | 0.5 | 用于筛选 RoMa 对应点，范围 0.1–0.95。更高通常保留更少匹配；没有匹配时可适度降低。不是按钮识别概率或安全成功率。 |
| 匹配点上限 | 10000 | 高置信度点多于上限时按索引均匀抽取，用于估计 H。范围 500–10000。提高可能改善空间覆盖，但增加几何处理时间；降低不减少网络前向计算。 |
| 几何误差阈值 | 3 px | MAGSAC 配准的重投影误差阈值，位于实时原图像素坐标中。范围 0.5–10。过低可能丢弃有效匹配，过高可能接纳错配。 |
| 粗分辨率 | 560×560 | 官方完整模型全局匹配输入。当前固定，未通过降低分辨率获得加速。 |
| 精细分辨率 | 864×864 | 官方局部精修分辨率。当前固定；最终坐标恢复到原图像素单位。 |
| 基准特征缓存 | 开启 | 基准图粗、细特征驻留显存，后续只重新提取新照片特征。另缓存基准图的预处理张量；标定框的修改不会改变基准图，不需要重新计算图像特征。 |
| 模型常驻、预加载与预热 | 自动 | 开启网页时后台加载 settings.json 中指定的权重（默认 outdoor），并用基准图预热。首次较慢，后续避免反复读权重和初始化。页面状态栏显示进度。切换权重仍需重新等待。 |
| cuDNN benchmark | 开启 | 针对固定推理尺寸选择较快的 GPU 卷积实现，可能增加首次预热时间和临时显存。未开启降低矩阵乘法精度的 TF32 优化。 |
| 几何一致性最低数量/比例 | 8 / 20% | 低于阈值拒绝输出。仅是当前基本质量门槛，不能保证正确；尚未增加独立面板区域匹配点过滤或遮挡识别。 |
| 原图矩形 x1,y1,x2,y2 | 用户标定 | 左上原点，x 向右、y 向下。范围 0≤x1<x2≤原图宽，0≤y1<y2≤原图高。保存所有 11 个框后才允许匹配。 |

## 返回哪些区域数据

每个 buttons 元素均包含：

| 字段 | 用途 |
|---|---|
| name | 原来的 key_* 类别名，可用于 /set_interest 目标选择的适配。 |
| reference_rect_xyxy | 已保存的基准图矩形。 |
| polygon_xy | 基准矩形左上、右上、右下、左下四角，经 H 变换后的四边形顶点。 |
| bbox_xyxy | 四边形的水平外接框，向外取整并裁剪到实时图片，顺序 x1,y1,x2,y2。完全在图像外时为 null。可替代 YOLO 框用于裁剪区域。 |
| center_xy | 参考矩形中心经过 H 的投影；不一定等于外接框中心或四角平均值。 |
| polygon_area_px | 完整投影四边形的连续几何面积，包含图像外的部分，单位 px²。 |
| visible_polygon_area_px | 与图像范围相交后的几何面积；“visible”仅指落在图像范围内，不表示检测过遮挡。 |
| bbox_area_px | 裁剪后外接框的宽×高，单位像素面积。 |
| mask_area_px | 掩膜中区域内像素的实际数量，按像素中心是否落在四边形内计算。 |
| mask_file / mask_url | 原始实时图分辨率的单按钮 PNG，255 表示区域内、0 表示外部。 |
| fully_inside_image / intersects_image | 是否完全位于图片内、是否有区域内像素；不表示按钮可见。 |
| requires_visibility_check | 当前始终为 true：仍需人工或其他算法核验按钮身份与遮挡。 |

倾斜视角下矩形会变成四边形。外接矩形会包括一些真实按键区域之外的像素，因此它与精确区域面积不同。若你保持“框内深度均值”，可直接使用 bbox_xyxy；若背景深度干扰明显，可用掩膜筛掉外接框角落的背景。

以下是另一台电脑接入时的示例，不表示本机已连接深度相机：

```python
# depth 已与此次实时 RGB 原图对齐，尺寸相同。
# bbox 的 x2/y2 为切片结束位置，不包含该列/行。
box = button["bbox_xyxy"]
if box is not None:
    x1, y1, x2, y2 = box
    region = depth[y1:y2, x1:x2]
    valid = np.isfinite(region) & (region > 0)
    mean_depth_m = float(region[valid].mean()) * depth_scale if valid.any() else None
```

若使用掩膜，在 valid 条件上再加 `mask[y1:y2,x1:x2] > 0`。远近阈值、内缩比例、最少有效点数和统计方法应沿用实际机器人程序的定义。深度单位例如毫米转米的 0.001，必须以相机输出为准。

## 精度边界

H 假定面板近似平面。显著凸起的按钮面、复杂背景、反光和遮挡可能影响映射。坐标来自固定模板，不是重新识别按钮名称。图片面积不能直接转换为物理面积、深度或机械臂距离；后续仍需对齐 RGB-D、相机内参和手眼变换。

## 性能验证

详见 performance.json。用你的固定基准图生成已知透视变化，完整 indoor 模型测试 3 次官方路径与 3 次缓存路径；两者分辨率及精度设置相同。已知点的映射误差约 0.11 像素，仅用于验证优化没有破坏坐标转换，不代表真实电梯按键误差。

热运行中位网络推理：官方约 1.92 秒，缓存约 1.13 秒，约 1.69 倍加速；基准图特征缓存约 246MB。权重加载约 6.2 秒，首次 cuDNN 算法选择/预热可额外花数十秒。网页总耗时还包含配准、11 张掩膜、图片和结果包写入，不能直接拿网络推理时间当作完整请求耗时。

本机为 8GB RTX 4060 Laptop。旧版和新版都加载完整模型可能显存不足；部署测试时已重启旧版释放其模型缓存，旧界面代码与记录仍保留。建议测试新版时不要同时在旧版运行匹配。

当前默认参数统一保存在 settings.json；网页、后台接口默认值和启动预热共用该配置。
